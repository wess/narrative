# Course 3 — Organization

Goal: keep a growing vault findable without spending all day maintaining a
perfect taxonomy.

## Lesson 1: Use the right organizing tool

Bethink gives you several ways to organize. They solve different problems.

| Tool | Best for | Avoid using it for |
|---|---|---|
| Folder | Broad ownership or lifecycle. | Every topic or subtopic. |
| Link | Connecting ideas and source pages. | Status tracking. |
| Tag | State, workflow, or cross-cutting themes. | Replacing clear titles. |
| Search | Retrieval when structure is uncertain. | Permanent categorization. |
| Daily note | Date-bound work and logs. | Long-term reference pages. |
| Template | Repeated page shapes. | Every possible writing style. |
| Table | Comparing similar pages. | Normal prose notes. |
| Graph | Seeing relationships. | Precise task management. |

## Lesson 2: Start with a small folder system

A good starter folder system:

```text
Inbox/
Projects/
Areas/
People/
Reference/
Archive/
```

What each folder means:

- **Inbox**: raw notes that need review.
- **Projects**: outcomes with an end state.
- **Areas**: ongoing responsibilities.
- **People**: notes about collaborators, customers, friends, or teams.
- **Reference**: stable information.
- **Archive**: inactive material you do not want in the way.

Keep this small until your real work proves you need more.

## Lesson 3: Use links for meaning

Links answer: "What is this connected to?"

Examples:

- A customer interview links to `[[Onboarding]]`.
- A project note links to `[[Launch Checklist]]`.
- A decision record links to `[[Pricing Strategy]]`.
- A person note links to projects you discussed with them.

When you make a link before the target exists, Bethink can create the page
later. This lets you connect ideas while you are thinking, not after you have a
perfect structure.

### Practice

Open one project page and add links to:

- A related person.
- A related decision.
- A related question.
- A related reference page.

Then inspect backlinks from one of those pages.

## Lesson 4: Use tags for workflow state

Tags are strongest when they describe state:

- `#status/active`
- `#status/waiting`
- `#status/done`
- `#type/decision`
- `#type/interview`
- `#review/weekly`
- `#review/needs-source`

Avoid vague tags:

- `#important`
- `#misc`
- `#stuff`
- `#todo`

If a tag does not change how you review, search, or act, you probably do not
need it.

## Lesson 5: Search like a power user

Use search operators when normal search is too broad:

| Query | Finds |
|---|---|
| `tag:review/weekly` | Pages marked for weekly review. |
| `title:roadmap` | Pages with roadmap in the title. |
| `content:budget` | Pages whose body mentions budget. |
| `/launch|release/` | Pages matching either word. |
| `tag:status/active onboarding` | Active pages that mention onboarding. |

Search is a pressure valve. If you can find something reliably, you do not need
to over-file it.

## Exercises

1. Create the starter folders or map your current folders to them.
2. Move five pages out of the root into the right broad folder.
3. Add three meaningful links to a page.
4. Replace one vague tag with a workflow tag.
5. Run five searches using operators.

## Power-user checkpoint

Your vault is organized when:

- Folders are broad and stable.
- Links carry meaning between ideas.
- Tags support review and workflow state.
- Search works because pages contain real words.
- The graph shows useful clusters instead of isolated notes.
