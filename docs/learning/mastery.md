# Course 10 — Bethink Mastery

Goal: combine the previous courses into a durable personal operating system.

## The power-user loop

Bethink mastery is a loop:

1. Capture.
2. Clarify.
3. Connect.
4. Review.
5. Reuse.
6. Automate.

Do not skip straight to automation. A workflow should be useful manually before
you turn it into an agent, plugin, or MCP process.

## Habit 1: Capture lightly

Capture raw material quickly:

- Meeting notes.
- Ideas.
- Questions.
- Links.
- Decisions.
- Project facts.

Do not organize everything while capturing. Put rough material in `Inbox`, a
daily note, or the relevant project page.

## Habit 2: Clarify within 24 hours

Raw notes decay fast. Within a day, add:

- A better title.
- One sentence of context.
- Links to related pages.
- Any decisions.
- Any next actions.

If a note is not worth clarifying, archive or delete it.

## Habit 3: Connect before filing

Filing asks: "Where does this live?"

Linking asks: "What does this mean?"

Power users link early, then move pages later if needed.

## Habit 4: Review on a schedule

Use:

- Daily shutdown for immediate next actions.
- Weekly review for open loops.
- Project review for active outcomes.
- Memory review when agents drift.
- Harness review before trusting repeated agent workflows.

## Habit 5: Promote durable knowledge

Daily notes and chat transcripts are not the final home for important facts.
Promote useful material into durable pages:

- Decisions.
- Project briefs.
- People notes.
- Reference pages.
- Checklists.
- Lessons learned.

## Habit 6: Make AI cite, then verify

When AI touches important work:

1. Ask for citations.
2. Open the cited pages.
3. Fix the source notes if they are stale.
4. Save the useful result as a normal page.

The best AI answers improve the vault, not just the chat transcript.

## Habit 7: Build trusted agent workflows

For repeated work:

1. Write the workflow manually.
2. Create an agent with a narrow role.
3. Limit tools.
4. Run it in a channel.
5. Inspect run history.
6. Curate memory.
7. Add a harness scenario.
8. Record pass/fail results.

Trust comes from observed behavior.

## Example weekly power-user workflow

1. Open `Weekly Review`.
2. Search for `#review/weekly`.
3. Search for open to-dos.
4. Open active project channels.
5. Ask AI to summarize open loops from linked pages.
6. Verify the cited pages.
7. Update project pages and decisions.
8. Review memory for active channels.
9. Record any repeated agent behavior in the harness.
10. Pin next week's active pages.

## Example project power-user workflow

1. Add the project folder.
2. Suggest a channel/team.
3. Keep read access on and write/run access off at first.
4. Ask the architect agent to explain the project structure.
5. Ask the reviewer agent to identify risks.
6. Approve only safe commands.
7. Ask the builder agent to propose a small change.
8. Review the proposal.
9. Run approved checks.
10. Save the outcome to channel memory.

## Maintenance checklist

Use this monthly:

- Are folder names still obvious?
- Are pinned pages still active?
- Are tags still useful?
- Are old project pages archived?
- Are daily notes feeding durable pages?
- Are AI memories accurate?
- Are agents still narrowly scoped?
- Are harness scenarios still relevant?
- Are plugins still needed?
- Is the vault backed up?

## Anti-patterns

Avoid:

- Building a huge taxonomy before writing real notes.
- Letting AI output live only in chat.
- Giving every agent every tool.
- Enabling project writes before reviewing proposals.
- Keeping stale memories because deleting feels risky.
- Installing plugins for workflows you have not practiced manually.
- Creating agents for tasks that a saved prompt can handle.

## Final power-user exam

Pick one real project and do this:

1. Create or clean its project page.
2. Link three supporting notes.
3. Add status and next action.
4. Ask AI to summarize risks with citations.
5. Verify citations.
6. Create a channel for the project.
7. Add one focused agent.
8. Attach the project folder if one exists.
9. Ask the agent for a small review.
10. Inspect run history.
11. Save one useful memory.
12. Create one harness scenario for the workflow.

If you can complete that without feeling lost, you are a Bethink power user.
