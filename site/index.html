Features

A second brain, backed by files — not a database.

Everything you'd want from a modern note-taking app, with plain Markdown as the source of truth.

📄

Your vault is a folder

Every page is a real .md file, every subfolder a folder. No proprietary database, no lock-in — back it up with git, sync it with anything, open it in any editor.

✍️

Block editor

A Notion-style writing surface with a slash menu, Markdown shortcuts, callouts, code, KaTeX math, tables, page embeds, and YAML page properties — round-tripping to Markdown on every save.

🔗

Linked, not foldered

[[Wiki links]] with live autocomplete, [[Page#Heading]] jumps, backlinks and outgoing-link panels, hover previews, and a global and local graph view.

🔎

Ranked full-text search

Find anything in milliseconds. Search is ranked and supports operators: tag:, title:, content:, and /regex/.

🗂️

Organisation

Drag-to-reorganise folders, nested #tags as a collapsible tree, daily notes, pinning, archive, templates, page icons, and a document outline.

🪟

Workspace

Tabs, a split-view reference pane, find in note (⌘F), a command palette (⌘K), random note, light / dark / auto theme, and persisted window state.

🤖

AI that knows your notes

A streaming chat drawer (⌘J) grounds answers in the page you're reading and/or your whole vault (RAG), plus one-tap page summarisation. Keys live in the OS Keychain.

☁️

Optional cloud sync

Stay fully local, or connect to a self-hostable Stohr instance for two-way sync — pages and attachments, with conflicts kept side by side.

🔌

MCP server & plugins

A standalone Model Context Protocol server lets Claude Desktop, Cursor, or Claude Code work with your vault. An Obsidian-compatible plugin API loads community plugins.

⚡

Native and fast

No bundled browser — Narrative uses each OS's own webview. A small binary, an instant cold start, and a window that feels like part of your OS.

How it works

Files on disk are the source of truth.

The database is a derived index, rebuilt from your files on every open — there is nothing persistent to go stale, and nothing to lock you in.

Point it at a folder

Open any folder of Markdown. Subfolders become folders; every .md file becomes a page.

Write in blocks

The editor round-trips to plain Markdown on every save. What you see is exactly what's on disk.

The index follows

Links, tags, and embeddings are re-derived from your files; a watcher folds in edits from git or other editors.

Ask and connect

Backlinks, the graph, ranked search, and an AI grounded in your vault turn notes into connected thought.

Architecture

Two processes, one typed IPC contract.

  • ✦Bun host process — the vault repo, file I/O, index sync, search, RAG, and AI providers.
  • ✦React webview — the editor, sidebar, graph, search, and settings, using each OS's native webview.
  • ✦Derived index — an in-memory SQLite index rebuilt from your files; the filesystem is always the source of truth.
  • ✦Built on butter + basket — Narrative's own desktop framework and @basket/* standard library, vendored in.
  • ✦Cross-platform — builds a single-file binary and native bundles for macOS, Linux, and Windows.
React webview (editor · graph) │ typed IPC channel contract │ Bun host (src/host/index.ts) │ ┌──────────┴───────────┐ Markdown files derived index (the vault) (in-memory SQLite)
Quick start

Running in a few minutes.

Narrative runs on Bun — install it first, then clone the repo and go.

terminal 
# clone the repo
git clone https://github.com/wess/narrative
cd narrative

# install deps and open the native window with hot reload
bun install
bun run dev

# build a single-file binary -> dist/narrative
bun run build

# run the standalone MCP server
bun src/mcp.ts

On first run Narrative seeds a starter vault — press ⌘N for a new page and ⌘K to open the command palette. See the docs for the full build and distribution guide.
